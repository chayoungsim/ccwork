## 이슈 1. 에디터에서 노트의 태그를 칩으로 표시한다

### 설명

`Note`에 `tags: string[]` 필드를 도입하고, 노트를 선택하면 `NoteEditor`에 태그가 칩 목록으로 보이도록 한다. 입력은 아직 없고 **읽기 전용 표시**까지만 구현한다. 타입·시드·컴포넌트 골격(`TagInput`)을 한 번에 관통하는 가장 얇은 슬라이스다. (ADR-001, ADR-004)

### 작업 범위

- `src/types/note.ts`: `tags: string[]` 추가
- `db.json`: 기존 노트 4건에 `"tags": []` 추가 (의도된 시드 변경). 시연용으로 일부 노트에는 태그 값을 넣어도 된다.
- `src/components/TagInput.tsx`: `tags`, `onChange` props의 제어 컴포넌트 골격. 이 단계에서는 `ul/li` 칩 목록 렌더링만
- `NoteEditor`: 로컬 state `tags`를 선택 노트 값(`note.tags ?? []`)으로 동기화하고 `<TagInput />` 렌더링
- 신규 노트 작성 시 `tags`는 `[]`

### 완료조건 (Acceptance Criteria)

- [ ] `Note` 타입에 `tags: string[]`가 있고 `npm run build` 타입 체크가 통과한다.
- [ ] `db.json`의 기존 노트가 모두 `tags` 필드를 가진다.
- [ ] 태그가 있는 노트를 선택하면 에디터에 태그가 칩으로 표시된다.
- [ ] 태그가 없거나 `tags` 필드 자체가 없는 레거시 노트는 빈 목록으로 오류 없이 표시된다.
- [ ] 노트 선택 전환 / 새 노트 작성 시작 시 태그 표시가 해당 노트 값으로 바뀐다.
- [ ] `TagInput` 렌더링 테스트(칩 표시, 빈 목록)가 추가되어 통과한다.

### 시나리오 (Given / When / Then)

**시나리오 1-1. 태그가 있는 노트 표시**

- **Given** `tags: ["react", "study"]`인 노트가 있고
- **When** 사용자가 목록에서 해당 노트를 선택하면
- **Then** 에디터에 `react`, `study` 칩 2개가 표시된다.

**시나리오 1-2. 레거시 데이터 방어**

- **Given** `tags` 필드가 없는 노트 데이터가 있고
- **When** 사용자가 해당 노트를 선택하면
- **Then** 오류 없이 태그가 빈 목록으로 표시된다.

**시나리오 1-3. 노트 전환 동기화**

- **Given** 태그 `react`가 있는 노트 A를 보고 있고
- **When** 태그가 없는 노트 B를 선택하면
- **Then** 에디터의 태그 목록이 비어 있다.

**시나리오 1-4. 새 노트 시작**

- **Given** 태그가 있는 노트를 보고 있고
- **When** 사용자가 "새 노트"를 누르면
- **Then** 태그 목록이 비어 있다.

## 이슈 2. 태그를 추가하고 저장하면 유지된다

### 설명

입력창에 태그를 입력하고 Enter 또는 쉼표로 칩을 추가한 뒤 "저장"하면 서버에 반영되어, 노트를 다시 열었을 때 태그가 유지된다. 정규화(`trim`, 선행 `#` 제거, 빈 값 무시)와 `addNote`/`editNote`의 `tags` 전달까지 UI → 유틸 → Context → API → `db.json`을 관통한다. (US-01, ADR-001·002·003)

### 작업 범위

- `src/utils/tags.ts`: `normalizeTag`, `validateTag`(이 단계는 정규화·빈 값 무시만), `MAX_TAG_LENGTH`/`MAX_TAG_COUNT` 상수 선언
- `TagInput`: 입력창, `keydown`의 `Enter`/`,` 처리, 입력값 로컬 state, 추가 후 입력창 초기화
- `NotesContext`: `addNote(title, content, tags)`로 시그니처 확장, `editNote`는 `tags`를 `Partial<Note>`로 전달
- `NoteEditor.handleSave`: 제목·내용·태그를 1회 POST/PATCH로 전송
- `src/utils/tags.test.ts`: 정규화 단위 테스트

### 완료조건 (Acceptance Criteria)

- [ ] Enter 또는 `,` 입력 시 칩이 추가되고 입력창이 비워진다. (쉼표 문자는 입력창에 남지 않는다.)
- [ ] 앞뒤 공백은 제거되고 선행 `#`은 제거된다. (`#react` → `react`)
- [ ] 빈 문자열 / 공백만 / `#`만 입력은 무시되며 메시지도 없다.
- [ ] 저장 시 기존 노트는 PATCH, 신규 노트는 POST 한 번으로 태그가 함께 전송된다.
- [ ] 저장 후 노트를 다시 열거나 새로고침해도 태그가 유지된다.
- [ ] 저장 전에는 서버(`db.json`)에 태그가 반영되지 않는다.
- [ ] 입력한 대소문자 표기가 그대로 저장된다. (`React` → `React`)
- [ ] `normalizeTag`/`validateTag` 단위 테스트와 `TagInput` 추가 동작 테스트가 통과한다.

### 시나리오 (Given / When / Then)

**시나리오 2-1. Enter로 태그 추가 후 저장**

- **Given** 태그가 없는 노트를 편집 중이고
- **When** 입력창에 `react`를 입력하고 Enter를 누른 뒤 "저장"을 누르면
- **Then** `react` 칩이 표시되고, 서버에 `tags: ["react"]`가 저장되며, 노트를 다시 열어도 `react`가 보인다.

**시나리오 2-2. 쉼표로 태그 추가**

- **Given** 입력창이 비어 있고
- **When** `study`를 입력한 뒤 `,`를 누르면
- **Then** `study` 칩이 추가되고 입력창은 비워진다.

**시나리오 2-3. `#` 접두사 정규화**

- **Given** 입력창이 비어 있고
- **When** `#react`를 입력하고 Enter를 누르면
- **Then** `react` 칩이 추가된다.

**시나리오 2-4. 빈 입력 무시**

- **Given** 입력창이 비어 있거나 공백 또는 `#`만 있고
- **When** Enter를 누르면
- **Then** 칩이 추가되지 않고 안내 메시지도 표시되지 않는다.

**시나리오 2-5. 신규 노트에 태그 포함 저장**

- **Given** "새 노트" 작성 중 제목·내용을 입력하고 태그 `idea`를 추가했고
- **When** "저장"을 누르면
- **Then** 생성된 노트가 `tags: ["idea"]`를 가진다.

## 이슈 3. 태그를 삭제하고, 취소하면 변경이 버려진다

### 설명

칩의 × 버튼으로 태그를 삭제하고 "저장" 시 반영한다. "취소"하거나 다른 노트로 전환하면 저장하지 않은 태그 변경(추가·삭제 모두)은 버려진다. 별도 취소 코드 없이 로컬 state + 일괄 저장 구조(ADR-002)로 US-05를 만족함을 검증한다. (US-02, US-05)

### 작업 범위

- `TagInput`: 칩별 삭제 버튼, `onChange`로 삭제 결과 전달 (`key`는 태그 문자열)
- `NoteEditor`: 취소 시 태그 state를 선택 노트 값으로 되돌림, 전환 시 동기화 확인
- `TagInput` 삭제 테스트, `NoteEditor` 저장/취소 통합 테스트 (`fetch` 모킹)

### 완료조건 (Acceptance Criteria)

- [ ] 칩의 × 버튼을 누르면 해당 태그만 목록에서 사라진다.
- [ ] 삭제 후 "저장"하면 서버에 반영되고 다시 열어도 삭제 상태다.
- [ ] 삭제 또는 추가 후 "취소"하면 태그가 원래 값으로 돌아가고 서버 요청이 발생하지 않는다.
- [ ] 저장하지 않고 다른 노트로 전환했다가 돌아오면 저장 전 상태(서버 값)가 보인다.
- [ ] 마지막 태그를 삭제해도 오류 없이 빈 목록이 된다.
- [ ] 위 동작에 대한 테스트가 통과한다.

### 시나리오 (Given / When / Then)

**시나리오 3-1. 삭제 후 저장**

- **Given** 태그 `react`, `study`가 있는 노트를 편집 중이고
- **When** `react` 칩의 × 버튼을 누르고 "저장"을 누르면
- **Then** `study`만 남고, 서버에 `tags: ["study"]`가 반영된다.

**시나리오 3-2. 삭제 후 취소**

- **Given** 태그 `react`가 있는 노트를 편집 중이고
- **When** `react`를 삭제한 뒤 "취소"를 누르면
- **Then** `react` 칩이 다시 표시되고 서버에는 아무 요청도 가지 않는다.

**시나리오 3-3. 추가 후 취소**

- **Given** 태그가 없는 노트를 편집 중이고
- **When** `temp` 태그를 추가한 뒤 "취소"를 누르면
- **Then** 태그 목록은 비어 있다.

**시나리오 3-4. 저장 없이 노트 전환**

- **Given** 노트 A에서 태그 `draft`를 추가했지만 저장하지 않았고
- **When** 노트 B를 선택했다가 다시 노트 A를 선택하면
- **Then** 노트 A에는 `draft`가 없다. (이탈 경고는 이번 범위가 아니다.)

## 이슈 4. 중복 태그를 차단하고 안내한다

### 설명

대소문자·공백 차이를 무시하고 이미 있는 태그와 같으면 추가를 차단하고 안내 메시지를 보여준다. 저장되는 표기는 처음 입력한 대소문자를 유지한다. (US-04, ADR-003)

### 작업 범위

- `src/utils/tags.ts`: `isDuplicateTag` 추가, `validateTag`에 중복 검사 통합 (`{ ok: false, message }`)
- `TagInput`: 안내 메시지 로컬 state와 표시 영역, 다음 입력 시 메시지 해제
- `tags.test.ts`에 중복 케이스 표 추가, `TagInput` 중복 차단 테스트

### 완료조건 (Acceptance Criteria)

- [ ] `React`가 있는 상태에서 `react`, `REACT`, `#react`를 추가하면 모두 차단된다.
- [ ] 차단 시 칩은 추가되지 않고 중복 안내 메시지가 표시된다.
- [ ] 기존 칩의 표기(`React`)는 변경되지 않는다.
- [ ] 입력을 다시 수정하거나 정상 태그를 추가하면 안내 메시지가 사라진다.
- [ ] 입력창의 값은 차단된 뒤에도 사용자가 수정할 수 있도록 유지된다.
- [ ] `isDuplicateTag`/`validateTag` 단위 테스트와 UI 테스트가 통과한다.

### 시나리오 (Given / When / Then)

**시나리오 4-1. 대소문자만 다른 태그**

- **Given** 태그 `React`가 있고
- **When** `react`를 입력하고 Enter를 누르면
- **Then** 칩이 추가되지 않고 중복 안내 메시지가 표시된다.

**시나리오 4-2. 접두사·공백이 다른 중복**

- **Given** 태그 `react`가 있고
- **When** `#React`를 입력하고 Enter를 누르면
- **Then** 정규화 후 중복으로 판정되어 차단된다.

**시나리오 4-3. 표기 유지**

- **Given** 태그 `React`가 있고 중복 시도가 차단되었고
- **When** "저장"을 누르면
- **Then** 서버에는 `["React"]`가 저장된다.

**시나리오 4-4. 메시지 해제**

- **Given** 중복 안내 메시지가 표시된 상태에서
- **When** 입력창 내용을 수정하거나 다른 태그를 정상 추가하면
- **Then** 안내 메시지가 사라진다.

## 이슈 5. 태그 길이(20자)와 개수(10개)를 제한한다

### 설명

한 태그는 최대 20자, 노트당 최대 10개로 제한한다. 한도를 넘는 시도는 차단하고 안내 메시지를 보여준다. 제한값은 `MAX_TAG_LENGTH`, `MAX_TAG_COUNT` 상수로만 조정한다. (성공 기준, ADR-003)

### 작업 범위

- `src/utils/tags.ts`: `validateTag`에 길이·개수 검사 추가 (정규화 후 길이 기준)
- `TagInput`: 차단 메시지 표시 (이슈 4의 메시지 영역 재사용)
- 경계값 단위 테스트 (20자 허용 / 21자 차단, 10개 허용 / 11번째 차단)

### 완료조건 (Acceptance Criteria)

- [ ] 정규화 후 20자 태그는 추가되고 21자 이상은 차단 + 메시지가 표시된다.
- [ ] `#`를 제외한 길이로 판정한다. (`#` + 20자 → 허용)
- [ ] 태그가 10개인 상태에서 11번째 추가는 차단 + 메시지가 표시된다.
- [ ] 개수 한도에 도달한 뒤 태그를 삭제하면 다시 추가할 수 있다.
- [ ] 제한값은 상수 두 개 변경만으로 조정되고, 테스트도 상수를 참조한다.
- [ ] 이미 저장된 한도 초과 태그(제한 변경 이전 데이터)는 검사·변경하지 않는다.
- [ ] 경계값 단위 테스트가 통과한다.

### 시나리오 (Given / When / Then)

**시나리오 5-1. 길이 경계**

- **Given** 입력창이 비어 있고
- **When** 정확히 20자 태그를 입력하고 Enter를 누르면
- **Then** 칩이 추가된다.

**시나리오 5-2. 길이 초과**

- **Given** 입력창이 비어 있고
- **When** 21자 태그를 입력하고 Enter를 누르면
- **Then** 칩이 추가되지 않고 길이 제한 안내 메시지가 표시된다.

**시나리오 5-3. 개수 초과**

- **Given** 태그가 이미 10개 있고
- **When** 새 태그를 입력하고 Enter를 누르면
- **Then** 칩이 추가되지 않고 개수 제한 안내 메시지가 표시된다.

**시나리오 5-4. 삭제 후 재추가**

- **Given** 태그가 10개이고 개수 제한 메시지가 표시된 상태에서
- **When** 칩 하나를 삭제한 뒤 새 태그를 추가하면
- **Then** 정상적으로 추가된다.

## 이슈 6. 한글 IME 조합 중 Enter 오입력을 막는다

### 설명

한글처럼 조합형 문자를 입력하는 도중의 Enter는 글자 확정용이므로 태그 추가로 처리하지 않는다. `keydown`에서 `e.nativeEvent.isComposing`을 확인한다. (US-07, ADR-004)

### 작업 범위

- `TagInput`의 `onKeyDown`: `isComposing`이 true이면 `Enter`/`,` 처리 중단
- 조합 중 / 조합 완료 후 키 이벤트 테스트 (`fireEvent.keyDown`에 `isComposing` 지정)
- 실제 한글 IME 수동 확인 체크리스트 (jsdom 테스트는 실제 IME를 보장하지 못함)

### 완료조건 (Acceptance Criteria)

- [ ] 조합 중(`isComposing: true`) Enter는 칩을 추가하지 않고 입력값도 지우지 않는다.
- [ ] 조합이 끝난 뒤 Enter는 정상적으로 칩을 추가한다.
- [ ] 한글 태그(`리액트`)를 입력하고 Enter 한 번으로 정확히 한 번만 추가된다. (마지막 글자 중복·누락 없음)
- [ ] 영문 입력 동작은 이슈 2와 동일하다.
- [ ] 단위 테스트가 통과하고, 실제 브라우저에서 한글 입력을 수동 확인한 결과가 PR에 기록된다.

### 시나리오 (Given / When / Then)

**시나리오 6-1. 조합 중 Enter**

- **Given** 입력창에서 한글 `리액ㅌ`를 조합 중이고
- **When** Enter를 누르면
- **Then** 칩이 추가되지 않고 글자 조합만 확정된다.

**시나리오 6-2. 조합 완료 후 Enter**

- **Given** 한글 `리액트` 입력이 확정되었고
- **When** Enter를 누르면
- **Then** `리액트` 칩이 한 번만 추가되고 입력창이 비워진다.

**시나리오 6-3. 영문 입력 회귀 없음**

- **Given** 영문 `react`를 입력했고
- **When** Enter를 누르면
- **Then** 이슈 2와 동일하게 칩이 추가된다.

## 이슈 7. 키보드·스크린리더 접근성을 보장한다

### 설명

마우스 없이 태그를 추가·삭제할 수 있고 스크린리더가 태그 목록·삭제 버튼·오류 메시지를 올바르게 읽도록 마크업을 정비한다. 태그 영역에 한정하며 기존 접근성 미흡 항목(삭제 확인 대화상자 등)은 범위가 아니다. (US-06, ADR-004)

### 작업 범위

- 입력창 `label`(`sr-only`)과 `id`/`htmlFor` 연결
- 칩 목록 `ul/li`, 삭제 버튼 `aria-label="{태그} 태그 삭제"`, 키보드 포커스 가능한 `button`
- 안내 메시지 `role="alert"` 및 입력창과의 연결(`aria-describedby`)
- 포커스 표시(focus-visible) 스타일, 삭제 후 포커스 처리 확인
- 테스트(`getByLabelText`, `getByRole`)로 접근성 속성 검증, `a11y-auditor` 에이전트로 점검

### 완료조건 (Acceptance Criteria)

- [ ] 입력창이 `label`로 식별되고 스크린리더에서 "태그" 입력창으로 읽힌다.
- [ ] Tab 키만으로 입력창 → 각 삭제 버튼 → 저장/취소 버튼 순으로 이동할 수 있다.
- [ ] 삭제 버튼이 Enter/Space로 동작하며 `aria-label`이 `"{태그} 태그 삭제"`다.
- [ ] 중복·길이·개수 오류 메시지가 `role="alert"`로 즉시 안내된다.
- [ ] 포커스된 요소에 눈에 보이는 포커스 표시가 있다.
- [ ] 태그 영역이 `@theme` 토큰 색상으로 충분한 대비를 가진다.
- [ ] 접근성 속성 테스트가 통과하고 `a11y-auditor` 점검의 Critical 이슈가 없다.

### 시나리오 (Given / When / Then)

**시나리오 7-1. 키보드만으로 추가**

- **Given** 키보드만 사용하는 사용자가 태그 입력창에 포커스했고
- **When** `react`를 입력하고 Enter를 누르면
- **Then** 칩이 추가되고 포커스는 입력창에 남아 연속 입력이 가능하다.

**시나리오 7-2. 키보드만으로 삭제**

- **Given** 태그 `react` 칩이 있고
- **When** Tab으로 삭제 버튼에 포커스한 뒤 Enter를 누르면
- **Then** 칩이 삭제된다.

**시나리오 7-3. 스크린리더 삭제 버튼 안내**

- **Given** 스크린리더 사용자가 `react` 칩의 삭제 버튼에 포커스하면
- **When** 버튼이 읽히면
- **Then** "react 태그 삭제"로 안내된다.

**시나리오 7-4. 오류 즉시 안내**

- **Given** 태그 `react`가 있고
- **When** 사용자가 `react`를 다시 추가하려 하면
- **Then** 중복 안내 메시지가 `role="alert"`로 즉시 읽힌다.

## 이슈 8. 모바일 폭에서도 태그 영역 레이아웃을 유지한다

### 설명

좁은 화면에서 칩이 줄바꿈되고 긴 태그가 영역을 넘치지 않도록 한다. 태그 영역만 대상이며 사이드바 `w-72` 고정 등 기존 반응형 미흡 항목은 범위가 아니다. (성공 기준)

### 작업 범위

- 칩 컨테이너 `flex-wrap`, 칩 `truncate`(+ `max-w`), 입력창 `w-full`
- 모바일(약 360px)·태블릿·데스크톱 폭에서 시각 확인 (Playwright 스크린샷 가능)
- 터치 대상 크기(삭제 버튼) 점검

### 완료조건 (Acceptance Criteria)

- [ ] 360px 폭에서 태그 영역에 가로 스크롤이 생기지 않는다.
- [ ] 칩이 많으면 여러 줄로 줄바꿈된다. (10개 태그 기준)
- [ ] 20자 태그가 칩 영역을 넘치지 않고 필요하면 말줄임(`truncate`) 처리된다.
- [ ] 삭제 버튼이 터치하기에 충분한 크기(권장 최소 24px 이상, 가능하면 44px 터치 영역)를 가진다.
- [ ] 360px / 768px / 1280px 스크린샷으로 레이아웃을 확인하고 PR에 첨부한다.

### 시나리오 (Given / When / Then)

**시나리오 8-1. 칩 줄바꿈**

- **Given** 뷰포트 폭이 360px이고 노트에 태그가 10개 있고
- **When** 에디터를 열면
- **Then** 칩이 여러 줄로 줄바꿈되고 가로 스크롤이 생기지 않는다.

**시나리오 8-2. 긴 태그 처리**

- **Given** 뷰포트 폭이 360px이고 20자 태그가 있고
- **When** 에디터를 열면
- **Then** 칩이 영역 안에 머물고 넘치는 텍스트는 말줄임 처리된다.

**시나리오 8-3. 데스크톱 회귀 없음**

- **Given** 뷰포트 폭이 1280px이고
- **When** 에디터를 열면
- **Then** 기존 에디터 레이아웃이 유지되고 태그 영역이 입력 필드와 버튼 사이에 자연스럽게 놓인다.
