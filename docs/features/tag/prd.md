# 태그 기능 PRD (뼈대)

> 참고 문서: `spec-fixed.md` (확정 스펙)
> 상태: 기술 결정(ADR) 4건 작성 완료 (A안 선택). Out of Scope 확정 대기.

## 1. 개요

### 배경

- 노트가 늘어날수록 성격이 비슷한 노트를 묶어 파악하기 어렵다.
- 현재 `Note`는 제목/내용/생성·수정 시각만 가지며 분류 수단이 없다.

### 목표

- 노트에 문자열 태그를 붙이고 뗄 수 있다.
- 노트 상세 화면(에디터)에서 태그 목록을 확인할 수 있다.
- 태그는 정규화와 중복 검사 규칙을 따른다.

### 성공 기준

- [ ] 노트에 태그를 추가하고 저장하면 다시 열었을 때 유지된다.
- [ ] 태그를 삭제하고 저장하면 반영되고, 취소하면 반영되지 않는다.
- [ ] 대소문자만 다른 태그(`React` / `react`)는 중복으로 차단된다.
- [ ] 태그 길이(20자)와 개수(10개) 제한이 동작한다.
- [ ] 키보드만으로 태그를 추가/삭제할 수 있고, 한글 입력 중 Enter가 오작동하지 않는다.
- [ ] 모바일 폭에서도 레이아웃이 깨지지 않는다.

### 제약

- 기존 구조 유지: 서버 데이터는 `NotesContext`, 폼 입력값은 `NoteEditor` 로컬 state
- 백엔드는 `json-server`(`db.json`) mock

## 2. 사용자 스토리

| ID    | 스토리                                                                      | 인수 조건                                                         |
| ----- | --------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| US-01 | 사용자로서, 노트에 태그를 추가해 노트를 분류하고 싶다.                      | Enter 또는 쉼표로 칩이 추가되고, 저장 시 서버에 반영된다.         |
| US-02 | 사용자로서, 잘못 붙인 태그를 삭제하고 싶다.                                 | 칩의 × 버튼으로 삭제되고, 저장 시 반영된다.                       |
| US-03 | 사용자로서, 노트 상세 화면에서 붙어 있는 태그를 한눈에 보고 싶다.           | 에디터에서 해당 노트의 태그가 칩 목록으로 표시된다.               |
| US-04 | 사용자로서, 같은 태그가 중복으로 붙지 않기를 원한다.                        | 대소문자·공백 차이를 무시하고 중복이면 차단 + 안내 메시지가 뜬다. |
| US-05 | 사용자로서, 저장 전에는 태그 변경을 되돌리고 싶다.                          | 취소 시 태그 변경이 반영되지 않는다.                              |
| US-06 | 키보드/스크린리더 사용자로서, 마우스 없이 태그를 다루고 싶다.               | 입력창 label, 삭제 버튼 `aria-label`, 오류 `role="alert"` 제공.   |
| US-07 | 한글 사용자로서, 입력 중 Enter가 의도치 않게 태그를 확정하지 않기를 원한다. | IME 조합 중에는 Enter로 추가되지 않는다.                          |

### 엣지케이스

- 빈 문자열 / 공백만 입력 / `#`만 입력 → 무시 (메시지 없음)
- `#react` 입력 → `react`로 저장
- 21자 이상 입력 → 차단 + 메시지
- 11번째 태그 추가 시도 → 차단 + 메시지
- 기존 노트(`tags: []`) 및 `tags`가 없는 레거시 데이터 → 빈 목록으로 처리
- 새 노트 작성 시작 / 노트 선택 전환 → 태그 state를 해당 노트 값으로 동기화

## 3. 기술 결정 (ADR)

> 아키텍처 3안(A. 로컬 state + 일괄 저장 / B. 편집 중 즉시 저장 / C. 정규화된 `tags` 리소스)을 7개 기준으로 비교한 뒤 **A안**을 선택했다. 아래 4개 결정은 모두 A안을 전제로 한다.

### ADR-001. 태그 데이터 구조와 저장 위치

- **Status**: 확정 (A안 선택)
- **Context**: 태그를 `Note`에 어떻게 담고 어디에 저장할지 정해야 한다. 서버는 `json-server`(`db.json`) mock이고, 이번 단계에는 태그 필터·검색·재사용이 없다. 기존 서버 데이터는 `NotesContext` 하나가 관리한다.
- **Decision**: `Note`에 `tags: string[]` 필수 필드를 추가해 노트 문서 안에 저장한다. `createNote`/`updateNote`는 기존 body에 `tags`만 실어 보내므로 API 함수를 새로 만들지 않는다. `addNote(title, content, tags)`로 시그니처만 확장하고, `editNote`는 `Partial<Note>`로 이미 `tags`를 받는다. `db.json` 기존 노트 4건에 `"tags": []`를 추가한다(의도된 시드 변경).
- **Alternatives**:
  - **C안: `tags` 컬렉션 + `Note.tagIds`로 정규화** — 거부. 이번 단계 요구사항(추가·삭제·표시)에는 불필요하다. 태그 생성과 노트 PATCH 2회 호출, 조인 selector, 시드 마이그레이션이 필요하고, 확정 스펙의 "태그는 문자열로 저장"과 어긋난다. 태그 관리·필터가 필요해지면 그때 재검토한다.
  - **태그를 쉼표 구분 단일 문자열(`tags: string`)로 저장** — 거부. 쉼표가 들어간 태그 처리와 분리·결합 코드가 매번 필요하고, 중복 판정과 삭제가 복잡해진다.
- **Consequences**:
  - (+) 변경 범위가 작고, `Note` 문서 하나로 조회·저장이 끝난다. 기존 Context·API 패턴을 그대로 쓴다.
  - (+) 이후 정규화로 옮길 때 `string[]` → 엔티티 변환이 단순하다.
  - (−) 태그가 노트별 복사본이라 이름 변경·병합·사용 횟수 집계가 불가능하다(Out of Scope).
  - (−) 같은 태그 문자열이 노트마다 중복 저장된다.
  - (−) `tags`가 없는 레거시 데이터를 위해 읽는 쪽에서 `?? []` 방어가 필요하다. 시드 변경이 `db.json`에 반영되기 전까지 유지한다.

### ADR-002. 태그 변경의 저장 시점

- **Status**: 확정 (A안 선택)
- **Context**: 칩을 추가·삭제할 때 서버에 바로 반영할지, 기존 "저장" 버튼에 묶을지 정해야 한다. 제목·내용은 이미 `NoteEditor` 로컬 state로 관리되고 "저장"에서 한 번에 PATCH/POST된다. 신규 노트는 저장 전에는 `id`가 없다.
- **Decision**: 태그도 `NoteEditor`의 로컬 state(`tags`)로 관리하고, "저장" 시 제목·내용·태그를 1회 PATCH/POST로 보낸다. "취소"하면 태그 변경도 버린다. `selectedNoteId`/`isCreating`이 바뀌면 `useEffect`로 태그 state를 해당 노트 값(신규는 `[]`)에 동기화한다. 서버 반영은 기존 방식대로 API 성공 후 응답값으로 state를 갱신하는 비관적 업데이트다.
- **Alternatives**:
  - **B안: 칩 변경마다 즉시 PATCH** — 거부. (1) 제목·내용은 저장 버튼, 태그만 즉시 저장이면 "취소"의 의미가 모호하고 US-05(저장 전 되돌리기)를 만족하지 못한다. (2) 신규 노트에는 `id`가 없어 로컬 버퍼와 즉시 저장의 이중 경로가 생긴다. (3) 태그 조작마다 `updatedAt`이 갱신되고 요청이 늘며, 실패 시 롤백 UI가 필요하다.
  - **낙관적 업데이트** — 거부. 기존 `NotesContext`는 비관적 업데이트이고, 이번 변경에서 패턴을 바꿀 이유가 없다.
- **Consequences**:
  - (+) 저장 경로가 `handleSave` 하나라서 동작이 예측 가능하고, 요청은 1회다. US-05를 별도 코드 없이 만족한다.
  - (+) 기존 "폼 입력값은 로컬 state" 패턴과 일치한다.
  - (−) 칩을 추가하고 저장하지 않은 채 노트를 전환하거나 창을 닫으면 변경이 사라진다. 이탈 경고는 이번 범위에 없다.
  - (−) 동기화 `useEffect`의 의존성을 `[selectedNoteId, isCreating]`로 제한한 기존 방식(`eslint-disable-line`)을 따르므로, 같은 노트가 서버에서 바뀌어도 폼에 반영되지 않는다.
  - (−) 저장 실패 시 기존처럼 `alert`로만 안내한다.

### ADR-003. 태그 정규화·중복·제한 규칙의 구현 위치

- **Status**: 확정 (A안 선택)
- **Context**: 정규화(trim, 선행 `#` 제거), 빈 값 무시, 대소문자 무시 중복, 길이 20자·개수 10개 제한을 어디에 두고 언제 검사할지 정해야 한다. 규칙은 단위 테스트로 검증 가능해야 하고 제한값은 조정 가능해야 한다.
- **Decision**: 규칙을 UI와 분리된 순수 함수 모듈 `src/utils/tags.ts`에 둔다. `normalizeTag`, `isDuplicateTag`, `validateTag`가 있고, `validateTag`는 `{ ok: true, tag }` 또는 `{ ok: false, message }`를 반환한다. 빈 값은 `message: null`로 조용히 무시한다. 제한값은 `MAX_TAG_LENGTH`, `MAX_TAG_COUNT` 상수로 분리한다. 검사는 클라이언트에서 칩 추가 시점에만 하고, 중복 판정은 대소문자를 무시하되 저장은 입력한 대소문자 그대로 유지한다.
- **Alternatives**:
  - **`TagInput`/`NoteEditor` 내부에 검사 로직 인라인** — 거부. 컴포넌트 렌더링 없이는 규칙을 테스트할 수 없고, 메시지와 규칙이 UI에 섞인다.
  - **서버(json-server 미들웨어)에서 검증** — 거부. `json-server`는 mock이라 검증 계층이 없고, 서버 검증은 Out of Scope다.
  - **`NotesContext`(`addNote`/`editNote`)에서 검증** — 거부. 입력 직후 즉시 안내 메시지를 보여주려면 칩 추가 시점의 검사가 필요하다. Context에서는 이미 저장 단계라 늦다.
- **Consequences**:
  - (+) 규칙이 순수 함수라 테스트가 빠르고 엣지케이스(빈 값, `#`만 입력, 21자, 11개, 대소문자 중복)를 표로 검증하기 쉽다.
  - (+) 상수만 바꿔 제한을 조정할 수 있다.
  - (−) 검사가 클라이언트에만 있어 API를 직접 호출하면 규칙을 우회할 수 있다. 서버 검증은 Out of Scope다.
  - (−) 에러 메시지 문구가 `utils`에 있어 UI 문구가 유틸 계층에 섞인다. 다국어 메시지는 Out of Scope이며, 필요해지면 메시지 코드로 분리한다.
  - (−) 제한값(상수)이 바뀌어도 이미 저장된 태그는 검사하지 않는다.

### ADR-004. 태그 입력 UI 컴포넌트 구조와 입력 처리(IME·접근성)

- **Status**: 확정 (A안 선택)
- **Context**: 태그 입력창과 칩 목록 UI를 어떻게 나누고, 한글 IME 조합과 접근성 요구(US-06, US-07)를 어떻게 처리할지 정해야 한다. `NoteEditor`가 이미 폼 상태와 저장 로직을 갖고 있어 더 커지는 것을 피하고 싶다.
- **Decision**: 입력창·안내 메시지·칩 목록을 `TagInput` 컴포넌트 하나로 분리한다. props는 `tags`, `onChange`뿐인 제어 컴포넌트이고, 입력 중인 문자열과 안내 메시지는 `TagInput`이 로컬 state로 가진다. `NoteEditor`는 내용 입력과 버튼 영역 사이에 `<TagInput tags={tags} onChange={setTags} />`만 렌더링한다. 키 입력은 `Enter`와 `,`로 칩을 추가하고, `e.nativeEvent.isComposing`이 true이면 처리하지 않는다. 접근성은 입력창에 `label`(`sr-only`), 칩 목록에 `ul/li`, 삭제 버튼에 `aria-label="{태그} 태그 삭제"`, 오류 메시지에 `role="alert"`를 쓴다. 칩은 `flex-wrap`으로 줄바꿈하고 긴 태그는 `truncate`한다.
- **Alternatives**:
  - **`NoteEditor` 안에 입력 UI 인라인** — 거부. 파일이 길어지고 입력 UI만 따로 테스트할 수 없다. 프로젝트 지침(컴포넌트 분리·재사용)과도 맞지 않는다.
  - **외부 태그 입력 라이브러리 도입** — 거부. 이 프로젝트는 외부 UI 라이브러리를 쓰지 않고, 필요한 기능이 적으며, IME 처리와 `@theme` 토큰 스타일링을 직접 제어하기 어렵다.
  - **`onChange`에서 쉼표를 감지해 분리** — 거부. 쉼표 포함 붙여넣기 일괄 분리는 Out of Scope이고, IME 조합 중 값 변화와 섞여 오동작하기 쉽다. `keydown` 방식이 조합 상태를 명확히 구분한다.
  - **칩 목록을 별도 `TagChip` 컴포넌트로 추가 분리** — 이번엔 보류. 칩이 단순해 분리 이득이 작고, 재사용 요구가 생기면 분리한다.
- **Consequences**:
  - (+) `NoteEditor` 변경이 최소이고, `TagInput`을 props만으로 단독 렌더·테스트할 수 있다(키 입력, IME, 메시지, 삭제).
  - (+) 접근성 요구가 컴포넌트 안에서 한 번에 충족되고, 반응형은 `flex-wrap`/`truncate`로 처리된다.
  - (−) 입력창·안내 메시지의 `id`(`tag-input`, `tag-message`)가 고정값이라 `TagInput`이 한 화면에 둘 이상이면 충돌한다. 재사용 시 `useId()`로 바꿔야 한다.
  - (−) 칩의 `key`를 태그 문자열로 쓰는데, 중복 금지 규칙에 의존한다.
  - (−) `isComposing`은 브라우저·IME 조합에 따라 동작 차이가 있어, jsdom 단위 테스트만으로는 실제 한글 IME를 보장하지 못한다. e2e나 수동 확인이 필요하다.
  - (−) Backspace 삭제, 자동완성, 칩 순서 변경은 지원하지 않는다(Out of Scope).

## 4. Out of Scope

이번 단계에서 하지 않는 항목이다. 필요해지면 별도 기능으로 분리한다.

### 표시

- 목록(`NoteList`/`NoteItem`) 카드의 태그 표시 (칩, `+N` 요약 포함)
- 태그 색상 지정, 아이콘 등 시각적 커스터마이징
- 태그 개수 배지, 상세 외 화면(헤더, 사이드바)에서의 노출

### 탐색

- 태그 기반 필터링, 검색, 정렬
- 태그 클릭 시 해당 태그 노트 모아보기
- 태그 URL 라우팅(딥링크)

### 입력 편의

- 쉼표가 포함된 문자열 붙여넣기 시 일괄 분리
- Backspace로 마지막 칩 삭제
- 자동완성, 기존 태그 추천, 최근 사용 태그
- 칩 드래그로 순서 변경, 칩 인라인 수정
- 모바일 전용 "추가" 버튼

### 태그 관리

- 전체 태그 목록 화면, 태그 이름 일괄 변경, 병합, 일괄 삭제
- 태그 사용 횟수 집계, 미사용 태그 정리
- 태그를 독립 리소스(별도 테이블/엔티티)로 관리

### 데이터·서버

- 서버 측 검증 (중복, 길이, 개수는 클라이언트에서만 검사)
- 태그 변경 즉시 저장(자동 저장), 낙관적 업데이트
- 다중 기기·다중 탭 간 동기화, 동시 편집 충돌 처리
- 기존 레거시 데이터를 일괄 변환하는 마이그레이션 도구

### 정책

- 태그 길이·개수 제한의 사용자 설정
- 대소문자 외 정규화(전각/반각, 유니코드 정규화, 특수문자 제한)
- 금칙어, 권한별 태그 정책, 다국어 안내 메시지

### 품질

- 목록 카드 변경 없음에 따른 신규 시각 회귀 테스트
- 성능 최적화(대량 태그, 가상화)
- 삭제 확인 대화상자 등 기존 접근성 미흡 항목의 일괄 개선 (태그 영역 외)

## 5. 용어 정의

| 용어            | 정의                                                                                      |
| --------------- | ----------------------------------------------------------------------------------------- |
| 태그(Tag)       | 노트에 붙이는 짧은 문자열 라벨. `Note.tags: string[]`의 원소.                             |
| 칩(Chip)        | 태그를 시각적으로 표현한 작은 UI 요소. 삭제(×) 버튼을 포함한다.                           |
| 정규화          | 입력 문자열을 저장 가능한 형태로 다듬는 과정. 앞뒤 공백 제거와 선행 `#` 제거.             |
| 중복 판정       | 정규화 후 대소문자를 무시하고 기존 태그와 같은지 비교하는 규칙.                           |
| 표기 유지       | 중복 판정은 대소문자를 무시하되, 저장은 사용자가 입력한 대소문자 그대로 하는 규칙.        |
| IME 조합        | 한글 등 조합형 문자 입력 중 상태. 이때의 Enter는 글자 확정이므로 태그 추가로 쓰지 않는다. |
| 상세 화면       | 이 문서에서는 `NoteEditor`(노트 편집 화면)를 가리킨다.                                    |
| 시드(Seed)      | `db.json`의 초기 노트 데이터.                                                             |
| 비관적 업데이트 | API 성공 후 응답값으로 state를 갱신하는 방식. 기존 `NotesContext`의 방식.                 |
